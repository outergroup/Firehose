Trace an Apple container

Apple Container runs each container in its own Linux VM. Its standard kernel lacks the tracepoints Firehose needs. Use a tracing-enabled kernel for the specific container you want to inspect.

1. Build the kernel on your Mac

The installed Firehose app includes a builder. It uses Apple Container by default; set OUTER_BUILD_CONTAINER_RUNTIME=docker to build with Docker instead. Allow several minutes and several GB of free space.

"$HOME/Library/Application Support/outershell/apps/org.outershell.Firehose/Firehose.app/Contents/Resources/kernel/build.sh"

This builder targets Apple silicon and Linux 6.18.15. It checks the installed kernel version, reuses Apple's installed configuration, verifies the source archive checksum, and enables Linux event tracing. It does not change your default kernel or existing containers. It prints the finished kernel path.

2. Create a container with that kernel

Use your image and retain its required mounts, environment variables and published ports. For example:

container create --name my-traced-container \
  --kernel "$HOME/Library/Application Support/org.outershell.Firehose/kernels/6.18.15-firehose/vmlinux-firehose" \
  --cap-add BPF --cap-add PERFMON --cap-add SYS_ADMIN --cap-add IPC_LOCK \
  YOUR_IMAGE
container start my-traced-container

The capabilities allow Firehose to load BPF programs, attach perf events, lock the capture buffers in memory, and mount tracefs inside this container's VM. They do not grant macOS administrator access. The image must include /usr/local/bin/outer-firehose-helper; new Outer Shell base images include it. For other images, copy the matching helper from Firehose's Contents/Resources/helpers into the image.

For an existing container, create a replacement with the same persistent storage and configuration. Keep the original until the replacement works; rebuilding a Dockerfile alone does not change an existing container's kernel.

3. Register it and open Firehose

Use Import container… in Outer Shell to register the new Apple container, then choose it on Firehose's landing page. Reload Firehose after changing the container setup.

Using a default kernel instead

Apple also supports container system kernel set --binary PATH for future containers. This changes the user-wide default, so the per-container --kernel option is preferable when only selected containers need tracing. Restore Apple's default with container system kernel set --recommended. Existing containers still need recreation with the chosen kernel and capabilities.
